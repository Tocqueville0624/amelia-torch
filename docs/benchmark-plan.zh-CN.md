## 2. 正确性门槛

1. **确定性内核**：条件均值、条件协方差、期望充分统计量、单步 EM 与最终参数，对照解析例子和 CPU float64；条件方差必须进入二阶矩，不能用均值填充冒充 EM。
2. **原版对照**：固定输入、列顺序、标准化、相同 bootstrap 行索引和初值。R 与 PyTorch 的同一个 seed 不产生相同随机序列；先用 `boot.type="none"` 或保存显式抽样索引隔离随机差异。原版返回参数在变换后的坐标，比较前转换到同一坐标。
3. **随机多重插补**：在原始样本而非 bootstrap 样本上补值，使用条件协方差产生噪声；固定环境可复现，不同副本有合理变异，已观测值原样保留。不要求跨后端每个随机补值逐位相同。
4. **统计质量**：MCAR、基于已观测变量的 MAR 模拟，考察均值/协方差、回归系数偏差、Rubin pooling 的标准误与 95% 覆盖率、区间宽度。RMSE/MAE 仅作辅助指标；均值填充可能降低 RMSE 却低估不确定性。MNAR 只作假设失效的压力测试。
5. **边界**：无缺失、全缺失列、全缺失行、常量列、近共线、`p >= n`、缺失比例高、抽样后全缺失列、非有限值、迭代上限。初版可明确拒绝不支持情况，不能静默改模型或返回成功。Amelia 的全缺失行处理须单独核对，不能盲目要求原版一定补满。

建议的初始容差（在看性能结果之前固定，并用条件数/问题规模说明调整）：良态标准化内核 CPU float64 `atol=1e-8, rtol=1e-6`；float32 `atol=1e-5, rtol=1e-4`。这些不是统计有效性的充分条件，也不保证病态输入能达到。至少 200 个独立模拟数据集作初筛，最终关键覆盖率配置建议 1,000 次；报告 Monte Carlo 标准误及区间，不把“差异不显著”当成等价证明。实用等价界限应预先登记。

## 3. 规模与缺失结构

先用小网格定位瓶颈，再增加规模，不一开始跑完整笛卡尔积。

- `n`：1,000 → 10,000 → 100,000；内存评估后再尝试 1,000,000。
- `p`：10、30、100；`m`：5、20，必要时扩到 50。
- 缺失比例：10%、30%、50%。
- 缺失模式：少量重复模式、块状/单调、独立随机缺失；记录实际不同模式数 K、组大小分布和完整行比例。
- 相关结构：良态协方差与高相关压力例子，逐个标明。
- 社会科学真实数据：优先后续核验许可的数据；Amelia 自带示例可作 API 兼容演示，不代表 GPU 目标规模。

计算峰值内存预算时包括输入/输出、掩码、所有活跃副本、充分统计量、分组缓存、临时 workspace。按副本/行分块；OOM 记录为 OOM，不从结果表删除。

## 4. 计时口径

**主指标**：同机端到端耗时，从内存中的原始输入开始，到 CPU/R 端可消费的全部 `m` 份结果完成；包括预处理、bootstrap、EM、抽样、输出重建及 GPU 传输。单独增加 R 调用路径，计入 reticulate/NumPy/R 转换。

另报进程冷启动/首次导入，以及常驻会话的稳态调用。CPU/原版/加速器采用相同的输入输出口径；不能用 GPU 内核时间对比原版完整调用。

每个配置预热 2 次，正式重复至少 5 次，采用预先固定的种子列表，交错或随机化实现运行顺序。报告所有原始耗时、中位数、IQR、每副本迭代数和收敛状态。数据生成不计入算法计时，但记录生成时间和数据哈希。

GPU 在计时开始前、停止前完成同步；参见 [PyTorch CUDA 异步执行说明](https://docs.pytorch.org/docs/2.14/notes/cuda.html#asynchronous-execution)。单独剖析预处理、分组、EM、随机抽样、桥接与传输。记录 CUDA 驱动/runtime、TF32 配置、CPU/MPS fallback、dtype、批大小、峰值 RAM/VRAM 和后台负载。准确性基准显式使用 IEEE FP32，TF32 或混合精度仅单列实验；参见[数值精度说明](https://docs.pytorch.org/docs/2.14/notes/numerical_accuracy.html)。

## 5. 成功标准与结果存档

- 正确性、统计质量、兼容性和速度分别给结论。单精度对照必须同时呈现质量结果。
- `speedup = baseline_end_to_end / candidate_end_to_end`，注明具体基线、硬件和口径。
- 达到预先设定的实用收益且重复稳定，才对该场景声称加速；可以先用“相对最佳合理 CPU 基线 ≥1.5×”作为工程目标，而非承诺。
- 展示全部代表性配置及 break-even 规模，不只挑最快的一行。若只比 Python CPU 快而没有超过原版 CPU 并行，应直接如此表述。
- 结果记录至少含 run ID、UTC 时间、代码提交/dirty 状态、依赖版本、OS、CPU/GPU、驱动、数据/配置哈希、种子、n/p/m/K、dtype、耗时、内存、收敛、质量指标、失败原因。
- 本地大文件放 `results/local/`，经过检查的小型可复现结果和说明放 `docs/validation/`；公开前去除私人路径及设备标识。
